Core Fundamentals

What Blockchain Actually Is

Blockchain / distributed ledger technology (DLT) is a shared system of record where multiple parties can validate and write transactions under agreed rules. Each block contains validated transactions, a timestamp, and the cryptographic hash of the preceding block — creating an immutable, append-only chain.

In finance, the value is less "crypto" and more shared infrastructure: near-real-time settlement, atomic delivery-versus-payment, programmability, and reduced reconciliation across firms. Even if an institution doesn't "touch crypto," it may touch clients, processors, custodians, or partners that do — creating indirect risk.

Key distinction

Most production financial deployments use permissioned / consortium blockchains (Hyperledger Fabric, R3 Corda, Quorum), not public chains. Driven by KYC/AML requirements, data privacy, finality guarantees, and need for known participants.

// Simplified block structure — financial-grade blockchain

Tokenization

From Assets to Tokens: The Spectrum

Tokenization is representing a claim or right — cash, deposits, securities, loans, funds, commodities, receivables — as a digital token on a ledger. This is how blockchain connects to traditional financial instruments and creates new risk dynamics.

A token mirrors an off-chain asset; the legal claim lives in traditional custody/registries. The token is a reference or receipt.

Examples: Tokenized T-bills (Ondo, Franklin Templeton), wrapped real estate interests, tokenized fund shares.

Risk: You inherit both traditional custody risk AND blockchain operational risk. Reconciliation between on-chain token state and off-chain asset state is a critical control.

Issuance, transfer, servicing, and lifecycle events occur on-chain, with legal frameworks making those actions binding. The token IS the asset.

Examples: Goldman Sachs GS DAP™, HSBC Orion (bonds), JPM Coin (deposits), USDC/USDT (stablecoins).

Risk: Greater efficiency but higher smart contract risk. Lifecycle events (coupons, maturities, corporate actions) are encoded in contract logic — bugs have direct financial impact.

ERM correlation warning

Tokenization can connect payments, liquidity, market, legal, third-party, and cyber risk in a single event. A depeg triggers liquidity stress + reputational + legal claims + customer runs simultaneously. ERM needs clear risk appetite: which chains, which assets, which counterparties, which geographies, and what "kill switches" exist.

Consensus Mechanisms

How Networks Agree on Truth

Consensus determines latency, throughput, finality, and fault tolerance. "Final" is protocol-dependent — operational playbooks differ fundamentally from ACH/wires/cards.

Hyperledger Fabric Quorum (IBFT)

Tolerates ⌊(n-1)/3⌋ faulty/malicious nodes. Three rounds: pre-prepare, prepare, commit. Deterministic finality in 1-3 sec, 1K-3K TPS. O(n²) complexity limits to ~20-100 validators.

Settlement finality

Deterministic finality = settled, aligning with EU Settlement Finality Directive. Directly impacts GL posting rules.

Fabric ordering Internal consortiums

Crash fault tolerant — tolerates offline nodes but NOT malicious behavior. Sub-second finality, higher throughput. Use when all participants are trusted.

Ethereum 2.0 Solana

Validators stake tokens as collateral. Economic security via slashing. Most regulated institutions interact via L2 solutions rather than running validators.

R3 Corda

No global broadcast. Point-to-point transactions, notary service prevents double-spends without seeing content. Mirrors how financial markets work — strong privacy by design.

Smart Contracts

"Code Is a Regulated Process"

Smart contracts encode business rules, compliance checks, and settlement logic. Regulators treat contract code as a regulated process — requiring formal governance, independent review, and change management.

Solidity — Tokenized Deposit
contract TokenizedDeposit is ERC20, Ownable {
    mapping(address => bool) public whitelisted;
    IComplianceOracle public complianceOracle;
    
    modifier onlyCompliant(address from, address to) {
        require(whitelisted[from] && whitelisted[to], "KYC required");
        require(!complianceOracle.isSanctioned(from) && 
                !complianceOracle.isSanctioned(to),
                "OFAC check failed");
        _;
    }
    
    function transfer(address to, uint256 amt) 
        public override onlyCompliant(msg.sender, to) 
        returns (bool) {
        require(dailyVol[msg.sender] + amt <= 250_000e18);
        dailyVol[msg.sender] += amt;
        return super.transfer(to, amt);
    }
}

Mandatory Governance Controls

Control Segregation of Duties

▼

Separate roles: mint/burn, reserve movement, contract upgrades, allowlist/denylist, pause authority. No single individual controls mint AND reserves. Multi-sig (2-of-3 / 3-of-5) on all admin functions.

Control Change Mgmt & Audit

▼

Formal change management + independent review. Min 2 audits from tier-1 firms (Trail of Bits, OpenZeppelin, Consensys Diligence). Formal verification for material-value contracts. Timelocked governance (24-72hr) on changes.

Control Operational Runbooks

▼

Documented runbooks: chain halts, bridge compromise, depegs, abnormal gas, validator events, oracle failures. Tested quarterly. Must cover 24/7 response.

Operational Risk

New Failure Modes

Blockchain introduces operational risks that don't exist in traditional banking. Transactions are irreversible, operations run 24/7, key loss = permanent asset loss.

Risk Private Key / Wallet Controls

▼

Failure modes: Loss, theft, privileged access misuse. Compromised key = irrevocable control. No "forgot my key."

Risk Irreversibility & Finality

▼

No chargebacks, recalls, or reversals. Pre-transaction controls are critical. Finality is protocol-dependent. L2 rollups: soft confirm in seconds, L1 finality may take days (optimistic). Define policies per chain.

Risk 24/7 Operations

▼

Staffing, incident response, liquidity ops, reconciliations, support — no longer "banker's hours." 24/7 on-call, automated monitoring, circuit breakers, weekend/holiday staffing for compliance and treasury.

Risk Blockchain-Native Fraud

▼

• Address poisoning — Tiny txns from lookalike addresses to trick copy-paste

• Spoofing — Malicious contract interactions disguised as legitimate

• Pig-butchering — Social engineering to attacker-controlled wallets

• Sanction evasion — Mixers, rapid hop chains, cross-DEX layering

• Smart contract exploits — Re-entrancy, oracle manipulation, flash loans, governance takeovers

Controls: Address verification UX, tx simulation, blockchain analytics (Chainalysis/TRM), consumer education.

Risk Third-Party (TPRM) Expansion

▼

New vendors: custodians, MPC providers, node infra, chain analytics, contract auditors, oracle providers, stablecoin issuers, exchanges, bridges, KYC providers.

Requirements: evidence of key custody controls, incident SLAs, audit reports, code audit scope, upgrade governance. Watch concentration risk — many "independent" vendors share same cloud/HSM stack. Right-to-audit and breach notification tailored to on-chain incidents.

Regulatory & Compliance

Navigating the Landscape

🇺🇸

U.S. Framework

OCC Letter 1174: DLT for payments/stablecoins. GENIUS Act: Payment stablecoin issuers, reserves, supervision. SEC: Howey test. FinCEN: BSA applies. Pre-notification required.

🇪🇺

EU / MiCA

EMTs (e-money tokens) and ARTs (asset-referenced tokens) with authorization, reserve, redemption requirements. Full enforcement June 2024. DORA: ICT risk management.

🌐

Basel & FSB

Group 1a/1b vs Group 2 (1250% risk weight). Disclosure framework Jan 2026. FSB global baseline for crypto oversight.

🔒

Data & Audit

GDPR vs. immutability: off-chain PII, on-chain hashes, crypto-shredding. FFIEC expects risk assessments, vendor DD, DR/key recovery.

Key management is a regulatory requirement

FIPS 140-2 Level 3+ HSMs, MPC/threshold signatures, documented key recovery, separation of duties, tested DR. Non-negotiable.

Core Legal Questions

What is the token legally? E-money token, asset-referenced token, deposit, security, stored value, prepaid access — varies by jurisdiction. MiCA classifies EMTs/ARTs explicitly. The U.S. has a stablecoin-specific framework post-GENIUS. Getting this wrong has cascading implications for capital treatment, licensing, consumer protection, and tax.

Redemption & consumer protection: Enforceable 1:1 redemption rights, timing, fees, segregation of reserves, insolvency treatment. Financial crime: AML/sanctions on a transparent but pseudonymous network requires new monitoring, typologies, and escalation. Cross-border: Stablecoin activity is global-by-default; regulators follow FSB's push for consistent oversight.
